Goal: Create a new API endpoint and service to handle multi-visualization course jobs using the existing HtmlInfographicStrategy.

1. New Controller & Endpoint:

    Create CourseController with a POST /v1/course-visualizations endpoint.

    It should accept the CourseJob JSON structure provided in @lesson_visualization.json (Metadata + Array of Visualizations).

2. CourseOrchestratorService:

    Create a new service that manages the "Batch" lifecycle.

    The Pre-Pass (Architect Call): Send the course_metadata to Gemini. Get back a global_style_anchor (a 20-word description of the visual vibe) and a hex-code mapping for the theme.

    The Loop: For each visualization in the array:

        Call HtmlInfographicStrategy.performGeneration.

        Pass the global_style_anchor as a override to ensure consistency.

    Concurrency: Use p-limit to process 3 visualizations at a time to avoid API rate limits while maintaining speed.

3. Storage & Result:

    Create a dedicated sub-folder for each course run: public/generated-images/courses/{course_id}/.

    The endpoint should return a list of URLs for all generated PNGs.

4. High-Throughput Test:

    Create scripts/test-full-course-run.ts using the provided JSON.

    Validation: The script should trigger the endpoint, wait for all 8 (or a subset of 3 for testing) images to generate, and log the final directory path.

How this will be validated:

    Running the test script should result in multiple PNGs appearing in the course folder simultaneously.

    All images must share the same #5B9A8B (Muted Teal) accent color.
